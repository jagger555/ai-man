## Summary

对 AI 数字人景区导览系统进行七项改进：检索切换为 jieba 分词 + 景区实体词典，规则+LLM 混合 query 分类，阿里百炼语音后端代理集成，知识库路线条目接入现有 RAG，LLM 自动生成标准测试集，行为数据 xlsx 接入数据大屏，以及 Prompt 追问引导。

## Problem Frame

当前系统具备文本问答、数字人播报、管理后台的完整骨架，但存在三个影响比赛交付的风险：检索依赖单字匹配和拍脑袋的置信度阈值，无法向评委证明 90% 准确率；语音交互完全缺失，演示视频缺少多模态亮点；16MB 官方行为数据未被利用，数据大屏的实际内容为空。此外，路线推荐模块尚未实现，追问体验偏被动。

## Key Decisions

- **jieba 分词 + 自定义景区实体词典，不做向量检索。** 关键词检索保持零模型依赖和分数可解释性；向量检索留到测试集基线建立后再评估是否引入。
- **Query 分类采用规则+LLM 混合（方案 C），不做纯 LLM 分类。** 常见类型（位置/票价/时间/推荐）用规则覆盖，模糊 query 才调用 LLM 分类，避免每次问答增加一次 API 调用。
- **语音走后端代理，不走前端直连。** 阿里百炼 API Key 不暴露给浏览器；代价是后端新增两个接口、音频数据在后端中转一次。
- **路线推荐用知识库条目 + RAG（方案 B），不做独立推荐模块。** 复用现有检索链路，零新代码，演示时可解释为"从知识库匹配最适合的路线"。
- **测试集用 LLM 自动生成种子，不做全人工标注。** 用 DeepSeek 遍历知识库每条知识点生成 1-2 个标准问题+参考答案，再人工抽检校准。

## Requirements

### 检索增强

- R1. 引入 jieba 分词替换当前单字拆分，`_query_terms()` 返回 jieba 切分的词语集合而非逐字集合。
- R2. 支持自定义景区实体词典，至少覆盖知识库中出现的所有景点名、建筑名和专有名词。
- R3. 新增 `_classify_query()` 函数，规则覆盖位置、票价、时间、推荐四种 query 类型，每种类型定义针对性加权字段；规则无法确定时调用 LLM 分类。
- R4. 扩展 `_score()` 的领域加权逻辑，从当前仅 `_is_height_query()` 扩展到全部已支持的 query 类型。

### 语音集成

- R5. 新增 `POST /api/speech/recognize` 接口：接收前端上传的音频 blob，调用阿里百炼 ASR API，返回识别文本。
- R6. 新增 `POST /api/speech/synthesize` 接口：接收文本，调用阿里百炼 TTS API，返回合成音频。
- R7. 前端游客问答区域新增麦克风按钮：录制音频 → 调 `/api/speech/recognize` → 自动填入输入框。
- R8. 前端回答区域新增播放按钮：点击 → 调 `/api/speech/synthesize` → 播放返回的音频。
- R9. 语音服务不可用时前端给出明确状态提示，不崩溃，文本问答仍可正常使用。

### 路线推荐

- R10. 在知识库中新增 4-5 条路线文档（经典一日游、文化深度游、亲子休闲游、摄影打卡游、半日精华游），每条包含路线顺序、推荐理由、讲解重点。
- R11. 新增 `_is_route_query()` 规则，对"路线/怎么玩/推荐/安排"类 query 在检索时对路线分类条目加权。
- R12. 路线推荐结果通过现有 `/api/chat` 接口返回，LLM 在 Prompt 引导下以导游语气展开路线内容。

### 评测体系

- R13. 用 DeepSeek 遍历 `data/sample_scenic/knowledge.md` 的知识点，每条知识点生成 1-2 个标准问题+参考答案，产出 30-50 题的标准测试集 JSON 文件。
- R14. 新增评测脚本 `backend/tests/test_accuracy.py`：逐题跑 `/api/chat`，对比回答与参考答案，统计准确率、可靠率、无资料来源率。
- R15. 评测结果接入管理后台 `/api/admin/dashboard`，在大屏展示当前准确率指标。

### 行为数据可视化

- R16. 解析 `示范景区公开资料包/景点景区旅游数据行为分析数据.xlsx`，提取可用于大屏展示的汇总指标。
- R17. 汇总指标接入 `/api/admin/dashboard` 返回体，前端数据大屏新增对应卡片。

### 追问引导

- R18. 在 `prompt_service.py` 的 `build_prompt()` 中，Prompt 模板末尾追加追问引导指令："回答结束后，提出一个游客可能感兴趣的追问，引导对话继续。"

## Key Flows

- F1. 语音问答完整链路
  - **Trigger:** 游客点击麦克风按钮开始录音
  - **Steps:** 浏览器录音 → 前端上传音频至 `/api/speech/recognize` → 后端调百炼 ASR → 返回文本填入输入框 → 用户确认/编辑后发送 → 正常问答流程 → 回答返回后点击播放按钮 → 前端调 `/api/speech/synthesize` → 后端调百炼 TTS → 返回音频 → 浏览器播放
  - **Covered by:** R5, R6, R7, R8, R9

- F2. 路线推荐链路
  - **Trigger:** 游客提出路线类问题（如"我想带老人玩半天怎么安排"）
  - **Steps:** `_is_route_query()` 命中 → 检索加权路线分类条目 → RAG 返回 Top-3 路线 chunk → Prompt 组合路线内容 + 游客偏好 → LLM 按导游语气展开路线顺序和讲解重点 → 返回结构化路线回答
  - **Covered by:** R10, R11, R12

## Acceptance Examples

- AE1. 游客问"灵山大佛多高" → jieba 正确切分为 ["灵山大佛", "多高"] → `_is_height_query()` 命中 → 高度相关 chunk 加权 → 返回含"通高88米"的回答。
- AE2. 游客问"灵山梵宫有什么好玩的" → jieba 分词后无明显类型命中 → LLM 分类为"推荐" → 检索加权推荐类条目 → 返回含演艺、体验项目的回答。
- AE3. 游客语音输入"灵山大佛有什么历史渊源" → 后端 ASR 识别正确 → 问答正常 → TTS 合成语音可播放。
- AE4. 数字人服务未启动时，语音问答仍可用——ASR 和 TTS 独立于 LiveTalking，不依赖 WebRTC 连接。
- AE5. 测试集 50 题跑完后，评测脚本输出准确率 ≥ 85%（作为基线，后续迭代改进至 90%）。

## Success Criteria

- 标准测试集准确率达到 90% 以上。
- 语音问答从录音结束到 TTS 开始播放的端到端延迟控制在 5 秒以内。
- 路线推荐在 5 种典型问法（"怎么玩""带老人""拍照""半天""深度游"）下均能命中对应路线条目。
- 行为数据大屏卡片在无 xlsx 文件或解析失败时给出明确空状态，不影响其他卡片渲染。

## Scope Boundaries

**Deferred for later:**
- 向量/语义检索——等测试集基线建立后，若关键词检索达不到 90% 再评估
- 多模态图片识别（拍照识景）——赛题可能加分，但当前链路过长
- 语音打断（barge-in）——百炼 TTS 支持流式，但复杂度高，先做非流式

**Outside this product's identity:**
- 移动端 App——比赛交付 Web 端即可
- 真实 GPS 地图导航——路线推荐以文本顺序输出为主

## Dependencies / Assumptions

- **阿里百炼 API 可用且返回格式稳定。** ASR 支持常见音频格式（WAV/MP3），TTS 返回音频 URL 或二进制流。
- **jieba 分词在景区中文场景下表现达标。** 若基础词典覆盖不足，通过自定义实体词典补强。
- **行为数据 xlsx 包含可解析的游客行为汇总。** 若内容为原始日志或不可解析格式，改为展示 xlsx 的元数据摘要。
- **DeepSeek 自动生成的测试问题质量可达人工抽检标准。** 需人工抽检至少 20% 的生成题目并校准参考答案。

## Outstanding Questions

- 阿里百炼 ASR 是否支持实时流式识别（边说边出字），还是只支持整段上传后返回？如果只支持整段，前端录音交互需要做"按住说话，松开发送"。
- 行为数据 xlsx 的具体表结构和字段含义需要实际读取后才能确定大屏展示内容。
